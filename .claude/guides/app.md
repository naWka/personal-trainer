# Приложение: правила изменений

Читай этот файл только при изменении сайта, экранов или `assets/app.js`.

## Приоритеты

Данные важнее интерфейса. `data/` не переписывать и не терять; UI можно
свободно переделывать. Экраны:

- **План** — будущие выбранные тренировки.
- **Журнал** — проведённые сессии, календарь и числа.
- **Мышцы** — готовность групп по модели `knowledge.md` §13.
- **Кольцо** — Oura и тренировки.
- **Отчёт** — закрытые периоды из `reports.json`.
- **Заметки**, **Справочник**.

Не возвращать отклонённые экраны «Прогресс» и «Запись» без просьбы атлета.
Старые ссылки `#today` и `#calendar` поддерживает `VIEW_ALIAS`.

## Рендеринг и навигация

- Старт всегда с «Плана»: `bootRoute()` стирает сохранённый hash. Не заменять
  его вызовом `route()` при старте.
- Экран рисуется один раз через `ensureView(view)` и обновляется только при
  отметке в `STALE`. Переключение вкладки меняет `hidden`, не пересобирает DOM.
- Обработчики локальных кликов вызывают `paint*`, не `render*`.
- Не использовать `scrollIntoView`. Вертикальная прокрутка не программируется;
  горизонтальные полосы центрируются через `keepInRow`.
- Не сочетать программную горизонтальную прокрутку со `scroll-snap`.
- `paintView` снимает `.anim` после `animationend`; анимация одноразовая.
- Использовать кэши `TONNAGE`, `DOSE`, `MS_STATE`, `GL_14`, `EX_HIST`,
  `OU_DAYS`, `SESSION_BY_DATE`, `HAY`.
- Диалоги блокируют прокрутку через `lockScroll()` и класс `locked` на `html`.
  Не возвращать `position: fixed` на `body`.

В журнале порядок блоков: календарь → тренировка выбранного дня → свёрнутая
легенда → вехи → числа → готовность групп. Между календарём и тренировкой
ничего не вставлять.

## Синхронность расчётов

- Модель готовности групп в `assets/app.js`, `scripts/planinputs.py` и
  `scripts/period_review.py` должна давать одинаковые числа.
- Изменил пороги `knowledge.md` §14 — обнови `OU_RULES`.
- Добавил поле дня Oura — добавь отображение в `OU_METRICS` или не сохраняй поле.
- Добавил упражнение — его `muscles.primary/secondary` должны разрешаться через
  `data/muscles.json`; это проверяет `scripts/validate.py`.
- Экран «Кольцо» строится из `data/oura.json` и `data/history.json`; отдельного
  наполнения нет.

После изменений: `python3 scripts/validate.py`, затем релевантные тесты и
проверка мобильного поведения.
